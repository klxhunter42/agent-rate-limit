# Claude API Request Anatomy

Complete breakdown of a Claude Code request through the ARL gateway, captured via MITM proxy.

---

## 1. URL

```
POST https://api.anthropic.com:443/v1/messages?beta=true
```

| Part | Value | Note |
|------|-------|------|
| Method | `POST` | All chat completions |
| Host | `api.anthropic.com` | Anthropic upstream |
| Path | `/v1/messages` | Messages API |
| Query | `?beta=true` | Enables beta features |
| HTTP | `HTTP/2.0` | Upstream uses h2 |

---

## 2. Request Headers

### 2.1 Authentication

```
authorization: Bearer sk-ant-oat01-<base64-encoded-token>
```

| Value | Source | Description |
|-------|--------|-------------|
| `sk-ant-oat01-...` | Claude OAuth | OAuth access token (from `claude login`). TTL ~1h, refreshed by gateway worker |
| `sk-ant-api03-...` | API key | Legacy API key (from console.anthropic.com) |

### 2.2 Anthropic-Specific

```
anthropic-version: 2023-06-01
anthropic-beta: claude-code-20250219,interleaved-thinking-2025-05-14,context-management-2025-06-27,prompt-caching-scope-2026-01-05,effort-2025-11-24,oauth-2025-04-20
anthropic-dangerous-direct-browser-access: true
```

| Header | Description |
|--------|-------------|
| `anthropic-version` | API version. `2023-06-01` is current stable |
| `anthropic-beta` | Comma-separated beta flags. Controls feature access |
| `anthropic-dangerous-direct-browser-access` | Allows browser-originated requests. Always `true` for Claude Code |

**Beta flags breakdown:**

| Flag | Purpose |
|------|---------|
| `claude-code-20250219` | Enables Claude Code-specific behavior |
| `interleaved-thinking-2025-05-14` | Extended thinking with interleaved content |
| `redact-thinking-2026-02-12` | Redact thinking blocks in response (Claude Code CLI >= 2.1.126) |
| `context-management-2025-06-27` | Context window management (auto-trim) |
| `prompt-caching-scope-2026-01-05` | Scoped prompt caching |
| `effort-2025-11-24` | Configurable inference effort (speed/quality tradeoff) |
| `oauth-2025-04-20` | **Critical**: OAuth authentication mode. Without this, OAuth token is treated as API key -> wrong rate limit bucket |

### 2.3 Client Metadata

```
user-agent: claude-cli/2.1.126 (external, claude-vscode, agent-sdk/0.2.141)
x-app: cli
x-claude-code-session-id: 953634b9-cf67-4d00-9d05-22113e70c567
```

| Header | Description |
|--------|-------------|
| `user-agent` | Client version, entry point, SDK version |
| `x-app` | `cli` or `vscode` |
| `x-claude-code-session-id` | UUID for session tracking |

### 2.4 Stainless SDK Headers


## 3. Request Body

```json
{
  "model": "claude-haiku-4-5-20251001",
  "max_tokens": 64000,
  "stream": true,
  "thinking": {"type": "adaptive"},
  "system": [...],       // 4 elements (see section 4)
  "messages": [...],     // conversation history (see section 5)
  "tools": [...],        // available tools (see section 6)
  "metadata": {          // user identification
    "user_id": "{\"device_id\":\"...\",\"session_id\":\"...\"}"
  },
  "output_config": {"effort": "high"}
}
```

| Field | Type | Description |
|-------|------|-------------|
| `model` | string | Target model ID. haiku: `claude-haiku-4-5-20251001`, sonnet: `claude-sonnet-4-6` |
| `max_tokens` | int | haiku: 64000, sonnet: 128000 |
| `stream` | bool | Always `true` for Claude Code (SSE streaming) |
| `thinking` | object | `{"type": "adaptive"}` = extended thinking with adaptive budget. Always set by Claude Code |
| `system` | array | System prompt as array of blocks (see below) |
| `messages` | array | Conversation turns (user/assistant) |
| `tools` | array | Tool definitions (Bash, Edit, Read, etc.) |
| `metadata.user_id` | string | JSON-encoded device + session IDs |
| `output_config` | object | `{"effort": "high"}` for full quality. Empty `{}` = defaults |

**Not set by default:** `temperature`, `top_p`, `top_k`, `stop_sequences`

## 4. System Array (4 Elements)

The `system` field is an array of objects. Each element has:
```json
{
  "type": "text",
  "text": "...",
  "cache_control": {"type": "ephemeral"}  // optional
}
```

### Element [0] - Privacy Guard (Gateway Inject)

```
type: text
cache_control: (none)
length: ~635 chars
source: ARL gateway (privacy/masking pipeline)
```

```
IMPORTANT: Your input contains special reference tokens in double-square-bracket
format, such as [[IP_ADDRESS_1]], [[ENV_USER_3]], or [[PHONE_NUMBER_2]]. These
tokens represent real data that has been anonymized.

You MUST:
- Preserve every token EXACTLY as written (same brackets, same label, same number)
- When referencing a value that a token represents, use the token itself verbatim
- NEVER output "undefined", "null", or any substitution for a token

Correct: "Connect to [[IP_ADDRESS_1]]"
Wrong:   "Connect to undefined"
Wrong:   "Connect to null"

Respond normally. Never mention privacy, masking, placeholders, or anonymization.
```

**Purpose:** Instructs Claude to preserve PII placeholders (`[[TYPE_N]]`) instead of replacing them with null/undefined. Injected by gateway when privacy masking is active.

**No cache_control:** This block changes per-request (different placeholder tokens), so caching is not applicable.

### Element [1] - Billing Header (CLI Inject)

```
type: text
cache_control: (none)
length: ~81-91 chars
source: Claude Code CLI
```

```
x-anthropic-billing-header: cc_version=2.1.126.345; cc_entrypoint=cli; cch=d1671;
```

| Field | Description |
|-------|-------------|
| `cc_version` | Claude Code version (e.g., `2.1.126.a1e` for VSCode, `2.1.126.345` for CLI) |
| `cc_entrypoint` | How Claude Code was launched: `cli`, `claude-vscode`, etc. |
| `cch` | Content hash (changes with different system prompt content) |

**Purpose:** Anthropic uses this header to classify requests into rate limit buckets. Different entrypoints may have different rate limits. This is why it's sent as a system element (text field) rather than an HTTP header - it's part of the prompt that gets billed and cached.

**No cache_control:** Changes per-session/version, not cacheable.

**Critical:** The optimizer's short-element guard (< 500 chars) MUST skip this element. Modifying or removing it reclassifies the request into a different rate limit bucket, potentially causing 429s.

### Element [2] - Identity (CLI Inject)

```
type: text
cache_control: {"type": "ephemeral"}
length: ~57-62 chars
source: Claude Code CLI
```

```
You are Claude Code, Anthropic's official CLI for Claude.
```

Or for Agent SDK:
```
You are a Claude agent, built on Anthropic's Claude Agent SDK.
```

**Purpose:** Tells Claude its own identity. Short but essential for correct behavior.

**`cache_control: ephemeral`:** Cached for 5 minutes. Small block, cheap to cache.

### Element [3] - Main System Prompt (CLI Inject)

```
type: text
cache_control: {"type": "ephemeral"}
length: ~25,000-28,000 chars (varies by CLI version)
source: Claude Code CLI
```

**Purpose:** Full behavioral instructions for Claude. Contains:
- Agent behavior rules (security, code style, output format)
- Tool usage guidelines
- Tone and style preferences
- Memory system instructions
- Context management rules
- CLAUDE.md / user instructions
- Output style rules
- Git status dump (current state of repo)

**`cache_control: ephemeral`:** Cached for 5 minutes. This is the **most expensive block** (~25-28K tokens). Prompt caching is critical here:
- First request: `cache_creation_input_tokens: 29942` (pays full price)
- Subsequent requests (same content): `cache_read_input_tokens: 29942` (cheaper, faster)

**Why optimizer breaks caching:** If the optimizer modifies element[3]'s text, the content changes, causing a cache miss every time. Instead of paying cache read price on subsequent requests, every request pays cache creation price. This wastes both tokens and money.

**Optimizer behavior on element[3]:**
- Element[3] is > 500 chars, so the optimizer DOES run on it
- 8 stages: semantic_dedup, chunker, delta, sketch, summarizer, textcomp, caveman, pordee
- Reduces size by ~5-10% but breaks prompt caching
- **Recommendation:** Skip element[3] optimization for transparent/OAuth requests where caching matters

## 5. Messages

Conversation turns between user and assistant. Each turn can contain multiple content blocks.

### Structure

```json
[
  {
    "role": "user",
    "content": [
      {"type": "text", "text": "<system-reminder>...skills..."},
      {"type": "text", "text": "<system-reminder>...CLAUDE.md..."},
      {"type": "text", "text": "user's actual message"}
    ]
  },
  {
    "role": "assistant",
    "content": [
      {"type": "text", "text": "Running short tests..."},
      {"type": "tool_use", "id": "toolu_01...", "name": "Bash", "input": {...}}
    ]
  },
  {
    "role": "user",
    "content": [
      {"type": "tool_result", "tool_use_id": "toolu_01...", "content": "..."}
    ]
  }
]
```

### Content Block Types

| Type | Direction | Description |
|------|-----------|-------------|
| `text` | both | Plain text content |
| `tool_use` | assistant | Tool invocation with `id`, `name`, `input` |
| `tool_result` | user | Tool output with `tool_use_id`, `content` |
| `thinking` | assistant | Extended thinking block (when enabled) |

### System Reminders

Claude Code injects `<system-reminder>` tags inside user messages for:
- Available skills list
- CLAUDE.md contents
- IDE selection context
- Git status

These are NOT in the `system` array; they're embedded in message content.

## 8. Response Body (SSE Stream)

Response uses Server-Sent Events format:

```
event: message_start
data: {"type":"message_start","message":{"model":"claude-haiku-4-5-20251001","usage":{"input_tokens":6,"cache_creation_input_tokens":29942,"cache_read_input_tokens":0,"output_tokens":1}}}

event: content_block_start
data: {"type":"content_block_start","index":0,"content_block":{"type":"text","text":""}}

event: ping
data: {"type": "ping"}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Hello"}}

event: content_block_stop
data: {"type":"content_block_stop","index":0}

event: message_delta
data: {"type":"message_delta","delta":{"stop_reason":"end_turn"},"usage":{"output_tokens":25}}

event: message_stop
data: {"type":"message_stop"}
```

### SSE Event Types

| Event | Description |
|-------|-------------|
| `message_start` | Message metadata + initial usage stats |
| `content_block_start` | New content block begins (text, tool_use, thinking) |
| `content_block_delta` | Incremental content (text delta, input/json delta) |
| `content_block_stop` | Content block ends |
| `message_delta` | Message-level updates (stop_reason, final usage) |
| `message_stop` | Stream complete |
| `ping` | Keep-alive |

### Usage Stats (message_start)

```json
{
  "input_tokens": 6,
  "cache_creation_input_tokens": 29942,
  "cache_read_input_tokens": 0,
  "cache_creation": {
    "ephemeral_5m_input_tokens": 29942,
    "ephemeral_1h_input_tokens": 0
  },
  "output_tokens": 1,
  "service_tier": "standard",
  "inference_geo": "not_available"
}
```

| Field | Description |
|-------|-------------|
| `input_tokens` | Non-cached input tokens |
| `cache_creation_input_tokens` | Tokens written to cache (first request, full price) |
| `cache_read_input_tokens` | Tokens read from cache (subsequent requests, discounted) |
| `output_tokens` | Generated output tokens |

**Cache lifecycle:**
1. First request: `cache_creation_input_tokens: 29942, cache_read_input_tokens: 0` -> pays creation price
2. Second request (same system): `cache_creation_input_tokens: 0, cache_read_input_tokens: 29942` -> pays read price (90% cheaper)
3. Cache expires after 5 minutes of inactivity (ephemeral TTL)

## 9. Error Response (429)

```
HTTP/1.1 429 Too Many Requests

x-should-retry: true
request-id: req_011Cb4JYij5j4jTfUFUoAiff

{"type":"error","error":{"type":"rate_limit_error","message":"Error"},"request_id":"req_011Cb4JYij5j4jTfUFUoAiff"}
```

| Field | Description |
|-------|-------------|
| `type` | Always `rate_limit_error` |
| `x-should-retry` | `true` = transient, safe to retry after backoff |
| No rate limit headers | 429 responses do NOT include utilization headers |

## 10. Gateway Request Flow

```
Claude Code CLI
    |
    | POST /v1/messages (Bearer token, system array, messages, tools)
    v
ARL Gateway (port 8080)
    |
    |-- Profile lookup (API key -> profile config)
    |-- Token pool selection (GetFromPool -> pick account with lowest utilization)
    |-- Privacy masking (PII -> [[TYPE_N]] placeholders)
    |-- System optimizer (8 stages, per-element, skip < 500 chars)
    |-- Budget level calculation
    v
Sidecar proxy (port 8081)
    |
    | Forward to api.anthropic.com with OAuth token
    v
MITM Proxy (port 8083)
    |
    | TLS termination + inspection
    v
api.anthropic.com
    |
    |-- Rate limit check (5h + 7d unified windows)
    |-- Prompt cache lookup (by content hash of system blocks)
    |-- Model inference
    v
SSE stream back through same chain
```

### What the Gateway Modifies

| Component | Modified? | How |
|-----------|-----------|-----|
| URL | Yes | Rewrites to upstream Anthropic URL |
| Authorization | Yes | Replaces client key with pool OAuth token |
| `anthropic-beta` | No | Passes through from client |
| System element[0] | Yes | Injected by privacy pipeline |
| System element[1] | No | Passes through (billing header, < 500 chars, skip guard) |
| System element[2] | No | Passes through (identity, < 500 chars, skip guard) |
| System element[3] | **Maybe** | Optimizer may modify (> 500 chars). **Breaks caching if modified** |
| Messages | Yes | Privacy masking on text content |
| Tools | No | Passes through |
| Model | Maybe | Profile may remap (e.g., `glm-5.1` -> `claude-haiku-4-5-20251001`) |

### What Should NOT Be Modified (for Cache Integrity)

- Element[3] text content (cache_control: ephemeral, ~28K tokens)
- Element[2] text content (cache_control: ephemeral)
- Any element with `cache_control` set

Modifying cached blocks forces cache recreation every request, negating the 90% cost savings from prompt caching.
