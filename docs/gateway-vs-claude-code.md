# Gateway vs Real Claude Code: Traffic Comparison

## Overview

This document compares how the ARL gateway proxies Claude API requests against how the real Claude Code CLI communicates with Anthropic's API directly. Understanding these differences is critical for debugging compatibility issues and ensuring seamless pass-through behavior.

---

## 1. Authentication

| Aspect | Real Claude Code CLI | ARL Gateway |
|---|---|---|
| Auth method | `Authorization: Bearer {oauth_token}` | Same - `AuthMode: "bearer"` for claude-oauth |
| Token source | `~/.claude/.credentials.json` -> `claudeAiOauth.accessToken` | Redis `arl:tokens:claude-oauth:{accountID}` |
| Token rotation | Single token, manual re-auth | Round-robin across multiple accounts, auto-rotation on 429 |
| Token refresh | CLI handles OAuth refresh internally | RefreshWorker every 30min + on-demand on 401 |
| Auth header | `Authorization: Bearer {token}` | Identical |

**Key difference:** Gateway can rotate between multiple OAuth accounts on 429, while real CLI uses a single account.

## 3. Request Body Transformations

### What the gateway modifies (real CLI does NOT do any of these)

| Transform | Trigger | Description |
|---|---|---|
| System prompt injection | Always (if enabled) | Prepends `[GATEWAY RULES]` and `[VISION]` instructions to system prompt |
| Model override | Profile routing | Profile can force a specific model or provider default |
| max_tokens override | Smart mode (default on) | Sets model-specific max_tokens if client didn't send one |
| Field stripping | Per-model logic | Removes `thinking`, `budget_tokens`, `effort` for haiku/3-5-sonnet |
| `context_management` removal | Non-Anthropic upstreams | Stripped for non-bearer providers |
| `service_tier` removal | Always | Always stripped |
| Privacy masking | Always (if enabled) | PII/secrets replaced with `[[TYPE_N]]` placeholders |
| Content filtering | GLM mode only | Removes `server_tool_use`, rewrites image blocks |
| System prompt optimization | Non-masked requests | Whitespace cleanup + sentence dedup |

### What passes through unchanged

- `messages` array (except privacy masking)
- `tools` definitions
- `temperature`, `top_p`, `stop_sequences`
- `stream` flag
- `metadata`

## 4. Streaming SSE Behavior

### Event relay (Anthropic native path)

The gateway acts as a transparent SSE relay for Anthropic-format responses:

| Event Type | Handling |
|---|---|
| `message_start` | Pass through + extract `input_tokens` for metrics |
| `content_block_start` | Pass through unchanged |
| `content_block_delta` | Pass through + unmask `text`/`thinking` fields if privacy masking active |
| `content_block_stop` | Pass through unchanged |
| `message_delta` | Pass through + extract `output_tokens` for metrics |
| `message_stop` | Pass through unchanged |
| `ping` | Pass through unchanged |
| `error` | Pass through unchanged |

### Differences from direct API

| Aspect | Direct API | Gateway |
|---|---|---|
| Event ordering | Unmodified | Identical (no reordering) |
| Event types | All pass through | Identical |
| Privacy unmasking | N/A | `[[TYPE_N]]` placeholders restored to original values |
| Stream timeout | None (client-side only) | 10-minute hard limit |
| Max line size | None documented | 256KB per SSE line |
| TTFB measurement | Client-side | Gateway measures for Prometheus metrics |
| Response headers | All headers from Anthropic | Filtered to allowlist (rate limit headers, Request-Id, Content-Type) |

## 5. Error Handling & Retry

| Aspect | Direct API (CLI) | Gateway |
|---|---|---|
| 429 handling | CLI shows error, user waits | Retry up to 3x with quadratic backoff, rotate account, 2min cooldown |
| 401 handling | CLI refreshes token | Gateway refreshes token + retry once |
| 503 handling | CLI shows error | Retry + cooldown |
| Backoff strategy | None (user retries manually) | `500ms * attempt^2`, capped at 5min |
| Account rotation | N/A (single account) | Rotates to next account in pool on 429 |
| Per-model cooldown | N/A | 2min cooldown per provider+model pair |

### Retry flow diagram

```
Request -> ProxyTransparent
  |
  +-- attempt 0: send to upstream
  |     +-- 429 -> rotateAccountFn -> next attempt
  |     +-- 401 -> oauthRefreshFn -> retry with new token
  |     +-- 2xx -> unmask + return
  |
  +-- attempt 1..N: same with backoff
  |
  +-- all retries exhausted -> return last error to client
```

## 6. Privacy Pipeline (PasteGuard)

Unique to gateway. Real CLI sends raw content to Anthropic.

### Masking (request -> upstream)

1. Extract text spans from: system prompt, message content, tool inputs
2. Detect secrets (regex): SSH keys, API keys (sk-, AKIA-, ghp-, glpat-), JWTs, connection strings
3. Detect PII (Presidio): PERSON, EMAIL_ADDRESS, PHONE_NUMBER
4. Replace with `[[TYPE_N]]` placeholders
5. Send masked payload to upstream

### Unmasking (upstream -> client)

1. Non-stream: bulk text replacement in response body
2. Stream: incremental chunk processing via `StreamUnmasker`
   - Buffers partial `[[...` placeholders that span SSE chunk boundaries
   - Unmask order: secrets first (innermost), then PII (outermost)
   - Handles `content_block_delta.text` and `.thinking` fields
   - Raw replacement for all other event types containing `[[`

## 7. Response Trimming

Gateway-only feature (configurable, default on):

Strips verbose AI patterns from text content blocks:
- "Here's the/a...", "Let me explain/show...", "I'll help you..."
- "Sure!", "Certainly!", "Of course!", "Great question!"
- "Hope this helps!", "Let me know if you need anything else..."

Applied only to non-stream responses, after unmasking.

## Known Issues

1. **Sonnet 429 org-level**: All claude-oauth accounts share org ID, rotation doesn't bypass org-level limits. Default model changed to haiku to avoid this.

2. **SSH to 192.168.5.221**: MITM capture requires SSH key authorization. Current keys not authorized on remote machine.

3. **Privacy filter in tool I/O**: `[[PERSON_X]]` markers appear in Claude Code's own tool output display, not in actual source files. Files on disk are clean (verified via `git diff`).
